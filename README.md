## 2. ROS2 笔记归档约定（`学习笔记/`，**只收 ROS2 问题**）

1. **一个「问题」一个文件**，命名 `序号_主题.md`（`01_`、`02_`…，**序号只增不减**）
2. **固定 9 段结构**（顺序别变）：
   ```
   1. 一句话结论          ← 先给答案
   2. 现象 / 报错原文      ← 原样抄，便于以后搜索
   3. 为什么会这样（原理）
   4. 最小复现            ← 能独立跑、不依赖大工程
   5. 要不要 / 什么时候用  ← 判断标准，不是背结论
   6. 正确 ✗ 错误 对照
   7. 口诀 / 排查清单
   8. 关联知识（路径、命令、文档出处）
   9. 一句话复述（自测）
   ```
3. **报错原文必须原样保留**（以后 Ctrl+F 搜报错就能命中）
4. 涉及自己的代码时**原文引用**，不要改写成"标准答案"——
   留着自己的思考痕迹才有用
5. **每新增一篇笔记，同步更新 `学习笔记/README.md` 的索引表**
6. 当前已有：`01`/`02`（09-20）+ **`03`/`04`（09-22，从我的工程 README 里的问题产出）** —— 完整索引见 `学习笔记/README.md`

### 2.1 ★ 双层笔记工作流（2026-09-22 定 · 我提出）

| 层 | 谁写 | 位置 | 内容 |
|---|---|---|---|
| **① 原始层** | **我** | 每个工程目录下 `src/README.md`（如 `w1_service_demo/src/READEME.md`） | **当天的问题、思考、自我批评**（允许乱、允许错、允许口语） |
| **② 成品层** | **AI 整理** | `~/ros2_study_myself/学习笔记/0X_*.md` | 9 段结构 + **源码行号/实测证据** + 索引 |
| **③ 闭环** | — | — | 新会话开始时 **AI 先读①**，就知道我今天有什么疑问；产出 ② 后我读到"排版好 + 准确"的笔记 |

**规则（以后照这个来）**：
1. ① 里的**问题原文**必须**原样保留**在 ② 的第 2 节（方便以后 Ctrl+F 搜索）；
2. ② 的结论**必须可验证**（给出源码路径:行号，或实测输出）；
3. **认领**：我读完 ② 后**用自己的话复述一遍**（"一句话结论"能脱稿讲出）→ 这篇才算真正"我的"；
4. 认领率记录在 §5 当前进度里（**今天的真实值：0 / 4**）。

## 3. 学习习惯（**请 AI 严格遵守**）

### 3.1 对我（自己）
1. **先自己判断，再动手试** —— 不要直接照抄 AI 的答案
   （实例：`01` 那篇，我自己先判断"外面已经保证存活，里面加指针没必要"，
   **这个直觉比两个网页版 AI 都准**）
2. **任何"AI 说的"都要在自己机器上跑一遍验证** —— 让报错教我，别让 AI 骗我
3. **卡住先对照参考源码**（`~/ros2_study_with_cline`），再来问原理
4. **收尾必落盘**：有问题就记进 `学习笔记/`，有代码就 commit

### 3.2 对 AI
| 要求 | 说明 |
|---|---|
| ❌ **不要直接改我的代码** | 至少要等我说"帮我改"。默认只**讲解 + 指方向** |
| ✅ **要给最小复现** | 讲原理时附上能独立编译运行的最小例子（像 `01` 那样） |
| ✅ **要给可验证的证据** | 能跑就跑（编译/运行/实测输出），不要只"推理 + 嘴说" |
| ✅ **要标注不确定性** | 不确定的地方直说，别装懂 |
| ❌ **不要擅自 git push** | 我说了才推 |
| ✅ **概念要落到我的场景** | 别把一个"异步场景的套路"硬套到我 `main()` 常驻节点上 |
| ✅ **帮我把问题归档** | 我说"记到学习笔记里" → 按第 2 节格式追加 + 更新索引 |
