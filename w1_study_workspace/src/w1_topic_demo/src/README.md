2.publisher和subscriber的定义
让我觉得很有意思的事情就是，句柄的概念，虽然句柄我的了解或许是错误的，我对句柄的概念就是create函数回传回来的智能指针，这个指针做的事情就是让我的publish类被创建之后，为了不造成内存泄漏的问题，需要用智能指针来管理，但是智能指针是有生命周期的，构造结束了之后就需要把临时智能指针传回去，不然没有引用计数，我的publish类也会被析构。
但是我之前一直在思考的一个问题就是，为什么不直接在构造publish等，这一类“功能”时候，直接把临时指针变成堆区的指针，但是现在思考了，如果做成堆区的指针，那么就会造成内存浪费，只需要一个智能指针指向publish这一类功能的类就行了，而且，rclcpp::Publisher<StringDate>::SharedPtr pub_;由于我的外部 auto node = std::make_shared<TopicPublishDemo>("w1_topic_publish"); 创建对象的时候，pub_也会被创建在堆区，如果有两个智能指针，那么做一个node对象被解析的假设，pub_虽然被释放了，但是内部的临时智能指针被我假定是堆区后的智能指针没有被我销毁，我的publish依然存在，其实想到这里，我暴露了一个很大的问题，就是对于内存生成这个概念我不是很熟悉，这直接决定我前面说的是不是对的，因为public我可以把他认定是我的  auto node = std::make_shared<TopicPublishDemo>("w1_topic_publish");对象的一员，那么我可以说，new的内存开辟是连续的空间，如果node被销毁，内部的临时智能指针被我假定是堆区后的智能指针内存也会被delete。所以这就是思想分歧的地方。
