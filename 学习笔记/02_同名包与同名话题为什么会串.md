# 02 · 同名包 / 同名话题为什么会"串"

> **记录时间**：2026-09-20
> **触发场景**：W1 手写练习时，我的包叫 `w1_topic_demo`，参考示例的包**也叫** `w1_topic_demo`、
> 可执行文件也都叫 `topic_publisher_node`；两边的发布者都在 `/w1/chatter` 上发消息。
> 结果：**订阅者收到了"别人"的消息**（见本文件夹 `01` 篇 §2 的实测日志）。
> **分类判定**：拿掉 ROS2 不成立（是 colcon/工作空间/ROS 图的问题）→ **ROS2 问题** → 归这里 ✅

---

## 1. 一句话结论

**三个"名字"的作用域层级完全不同，混用就会串：**

| 名字 | 作用域 | 规则 |
|---|---|---|
| **包名**（`project(w1_topic_demo)`） | **一个工作空间内** | 同名 → **`colcon build` 直接报错**（不允许重名） |
| **可执行文件名** | **包内** | 同名没关系，但 `ros2 run <包> <可执行>` 只认**最后被 source 的那个工作空间** |
| **话题名**（`/w1/chatter`） | **整个 ROS 域（全局）** | **同名 = 同一个话题** → 所有节点互相可见、消息混流（这就是"串"） |

> 三句话记牢：**包名是全局标识**（重名直接编译不过）、**话题名是契约**（两边必须一致才通）、
> **`source` 顺序决定你运行的是谁**（overlay 覆盖）。

## 2. 现象（实测原文，原样保留）

### 2.1 订阅者收到了"另一个发布者"的消息

```
[INFO] [w1_topic_subscriber]: 收到第 1 条：现在已经发送消息第2条     ← 这句是【我的 pub】的格式
[INFO] [w1_topic_subscriber]: 收到第 2 条：Hello ROS2 from W1! 第 3 条   ← 这句是【参考示例】的格式
```

同时 `ros2 node list` 里能看到**四个**节点（两个发布者都在）：

```
/capture_node
/drop_node
/keep_node
/w1_topic_publish
```

### 2.2 两个同名包放进同一个工作空间 → `colcon build` 报错原文

```bash
$ cd /tmp/w1_samename_ws && colcon build
[0.162s] ERROR:colcon:colcon build: Duplicate package names not supported:
- w1_topic_demo:
  - src/alpha/w1_topic_demo
  - src/beta/w1_topic_demo
```

---

## 3. 为什么会这样（原理）

1. **话题名是"全局契约"**：ROS2 用一个"域"（Domain，`ROS_DOMAIN_ID`）来隔离节点；
   同一个域里，**只要话题名相同**，发布者和订阅者就会通过 DDS 自动发现并连上 —— **不管它们在哪个包、哪个工作空间、哪个终端**。
   → 所以两个"都叫 `/w1/chatter`"的发布者，**天然会混流**，这是设计如此（方便组合，但也容易被误用）。
2. **包名是"查找键"**：`ros2 run <包> <可执行>` / `ros2 launch <包> ...` 都靠包名去 **`AMENT_PREFIX_PATH`**
   里按顺序找；`colcon` 则在**同一个工作空间里**要求包名唯一（否则它不知道往哪装）。
3. **overlay 覆盖机制**：每次 `source install/setup.bash`，就把这个工作空间**插到路径最前面** →
   **同名包时，后 source 的赢**（前面那个被"盖住"）。
   → 这就是"我明明改了自己的代码，跑出来却是旧行为/别人的行为"的经典原因。

## 4. 最小复现（3 分钟，全在 `/tmp`）

```bash
# ① 造两个【同名】包
mkdir -p /tmp/w1_samename_ws/src/alpha/w1_topic_demo /tmp/w1_samename_ws/src/beta/w1_topic_demo
# 每个包里放最小 package.xml（<name>w1_topic_demo</name>）+ CMakeLists（project(w1_topic_demo)）

# ② 编译 → 直接报重名（原文见 §2.2）
cd /tmp/w1_samename_ws && source /opt/ros/humble/setup.bash && colcon build

# ③ 换成两个【不同名】包，分别在两个工作空间编译，交替 source，观察 ros2 run 认哪个
source /tmp/ws_a/install/setup.bash ; ros2 pkg prefix w1_topic_demo   # 看指向谁
source /tmp/ws_b/install/setup.bash ; ros2 pkg prefix w1_topic_demo   # 换成后者
```

**同名话题混流的复现**（我实际就是这么撞上的）：
在两个终端分别跑**不同包**的发布者，但**话题名写成同一个** `/w1/chatter`，
再开第三个终端 `ros2 topic echo /w1/chatter` → 能看到两种格式的消息交替出现。

## 5. 要不要 / 什么时候用（判断标准 / 命名纪律）

| 场景 | 做法 |
|---|---|
| 自己练习 | 包名**带前缀**：`w1_my_topic_demo`、`zyx_topic_demo`（避免和教程/示例的 `w1_topic_demo` 撞） |
| 团队协作 | 包名统一前缀（如项目名 `lidar_car_*`）+ 每个包一个仓库/目录，避免重名 |
| 同时用多个工作空间（教程 + 自己练习） | **别同时 source**；要用哪个就开**新终端只 source 那个** |
| 必须在同一域里跑多套系统 | 用 **`ROS_DOMAIN_ID`** 隔离（`export ROS_DOMAIN_ID=1`），比如"教程一套、我自己一套" |
| 话题命名 | 加命名空间/前缀：`/w1/chatter`、`/my_car/cmd_vel`，避免和其他人的 `/chatter` 撞 |
| 观察到"消息来源不对" | `ros2 topic info /话题 -v`（看 Publisher/Subscriber 的具体节点名） |

## 6. 正确 ✗ 错误 对照

| ✗ 错误做法/认知 | ✅ 正确 |
|---|---|
| 两个包都叫 `w1_topic_demo` | 自己的包改名（`w1_my_topic_demo`），或分开放、别同时编译 |
| `colcon build` 报重名还硬要编 | 报错是**保护**：它会告诉你两个路径（见 §2.2），改名或删一个 |
| 以为"我 source 了就能跑我的" | 同名包看 **source 顺序**（后 source 的赢）；用 `ros2 pkg prefix` 确认 |
| 以为话题名无所谓 | 同名话题 **= 同一个话题**，会混流；不同系统要用不同话题名或 `ROS_DOMAIN_ID` |
| 改了代码但行为没变 | 先查：`source` 的是不是**这个**工作空间的 `install/setup.bash` |

## 7. 口诀 / 排查清单

> **口诀：包名唯一、可执行认 source 顺序、话题名全局唯一。**

| # | 症状 | 先查 |
|:---:|---|---|
| 1 | `ros2 run <包>` 跑的不是我改的代码 | `ros2 pkg prefix <包>`、`echo $AMENT_PREFIX_PATH`、确认 source 了哪个 `install/` |
| 2 | `colcon build` 报 `Duplicate package names` | 两个同名包路径（报错里给了）→ 改名 |
| 3 | 收到的消息"格式不对/内容陌生" | `ros2 topic info /话题 -v` 看有几个发布者；`ros2 node list` |
| 4 | 想隔离两套系统 | `export ROS_DOMAIN_ID=<不同数字>`（两端要一致才通信） |
| 5 | 想知道话题类型对不对 | `ros2 topic info /话题`（Type 必须两边一致） |
